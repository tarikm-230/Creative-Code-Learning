Beats, Smoothing & Events

This is the lesson that turns "it wiggles with the music" into "it hits with the music". You'll make values punchy but not jittery, detect kicks, and trigger events on the beat and on the drop.

You will learn

  • How to smooth values with lerp, plus the attack/release envelope (the pro technique)
  • How to detect beats by comparing energy against a running average
  • How to turn beats into events: bursts, flashes, color changes, and counting bars and phrases
  • How to tell a breakdown from a drop using slow energy

The jitter problem

Raw audio values change sharply from frame to frame, so visuals that use them directly look nervous. Simple smoothing with lerp (lesson 05) calms them down, but it also makes them slow, so the kick loses its punch.

The fix comes from audio engineering. It's an envelope follower: rise fast when the value goes up (the attack), and fall slowly when it goes down (the release). You get the instant hit followed by a smooth decay. That's what makes visuals feel "punchy".

function follow(current, target, attack, release) {
  if (target > current) {
    return lerp(current, target, attack);    // e.g. 0.6  → snaps up
  } else {
    return lerp(current, target, release);   // e.g. 0.08 → glides down
  }
}

Try this

  1. Change the release value from 0.08 to 0.02 (long tail), then to 0.3 (tight).
  2. Change the attack to 0.2. Feel how the punch softens.
  3. Rule of thumb: bass elements want attack 0.5–0.8 and release 0.05–0.15. Color and camera moves want much slower values (0.02–0.05), so they drift instead of jumping.

Beat detection

A kick drum is a sudden jump in bass energy. "Loud" alone isn't enough, because a track can be loud the whole way through. So we compare the current bass to its recent average:

bassAvg = lerp(bassAvg, bass, 0.05);          // slow-moving average
let isBeat = bass > bassAvg * SENSITIVITY     // clearly above average…
          && bass > MIN_LEVEL                // …and not just quiet noise…
          && millis() - lastBeat > 250;      // …and not right after the last beat

The cooldown (250 ms, a little faster than 1/8 notes at 128 BPM) stops one kick from counting twice. The graph below shows the bass energy (pink), the threshold line (white), and a flash whenever a beat is detected. Use ↑ and ↓ to tune the sensitivity live.

No beat detector is perfect It will miss some kicks in busy mixes and sometimes fire on a heavy bassline. That's normal. Professional VJ software has the same problem. Three ways to cope: tune the sensitivity for each track, design visuals that look fine even when a beat is missed, and (in the Setlist Engine) add a tap-tempo backup.

From beats to events

A detected beat is an event, a moment when you can do something. Counting beats unlocks musical structure: 4 beats = 1 bar, and 16 bars = a typical phrase, which is where DJ tracks usually change.

  • Every beat: a burst of particles, a flash, a scale "kick"
  • Every 4 beats (one bar): move to the next color in the palette
  • Every 32 beats (8 bars): change the shape or camera angle
  • Hi-hats (treble jumps): small sparkles. Use the same detection on 'treble'

Breakdowns and drops

A breakdown is a section where the bass is gone for a while. The drop is the moment it comes back. A very slow average of the bass (lerp with 0.01–0.02) tells you which section you're in. When it crosses a threshold, you've found a section change:

bassSlow = lerp(bassSlow, bass, 0.02);
let inBreakdown = bassSlow < 70;

if (wasBreakdown && !inBreakdown) {
  // 💥 THE DROP — do something huge
}
wasBreakdown = inBreakdown;

That last line is the edge detection pattern: remember last frame's state, and act only when it changes. You'll use it constantly.

💥 Challenge: Drop detector (25 min)

Build a sketch with two moods:

  • Breakdown mood: slow, calm, cool colors. For example, a noise blob that breathes with the mid band (the pads and arpeggio)
  • Main mood: punchy and warm, reacting to beats
  • On the drop (breakdown → main): a giant one-off event, like a white flash plus a burst of 300 particles
  • Tip: press → to jump ahead in the song so you can test the drop quickly. The demo's breakdown starts at 16 s and the drop hits at 20 s
Show one possible solution 
let flash = 0, sparks = [], env = 0, midEnv = 0;

function draw() {
  fft.analyze();
  let bass = fft.getEnergy('bass');
  let mid = fft.getEnergy('mid');
  bassSlow = lerp(bassSlow, bass, 0.02);
  let inBreakdown = bassSlow < 70;
  env = bass > env ? lerp(env, bass, 0.6) : lerp(env, bass, 0.1);
  midEnv = lerp(midEnv, mid, 0.05);

  if (wasBreakdown && !inBreakdown) {          // THE DROP
    flash = 1;
    for (let i = 0; i < 300; i++) {
      let a = random(TWO_PI), s = random(2, 14);
      sparks.push({ x: width / 2, y: height / 2, vx: cos(a) * s, vy: sin(a) * s, life: 1 });
    }
  }
  wasBreakdown = inBreakdown;

  if (inBreakdown) {
    background(220, 60, 12);
    translate(width / 2, height / 2);
    fill(200, 50, 90, 0.8);
    noStroke();
    beginShape();
    for (let a = 0; a < TWO_PI; a += 0.05) {
      let r = 60 + midEnv * 0.6 + 40 * noise(cos(a) + 1, sin(a) + 1, frameCount * 0.01);
      vertex(r * cos(a), r * sin(a));
    }
    endShape(CLOSE);
    resetMatrix();
  } else {
    background(15, 80, 10 + env * 0.1);
    fill(20, 90, 100);
    noStroke();
    circle(width / 2, height / 2, 60 + env);
  }

  for (let i = sparks.length - 1; i >= 0; i--) {
    let p = sparks[i];
    p.x += p.vx; p.y += p.vy; p.vx *= 0.96; p.vy *= 0.96; p.life -= 0.012;
    fill(40, 30, 100, p.life);
    circle(p.x, p.y, 5);
    if (p.life <= 0) sparks.splice(i, 1);
  }

  if (flash > 0.01) { background(0, 0, 100, flash); flash *= 0.9; }
}
